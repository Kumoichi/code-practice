このファイルはコンパイルされません（.go拡張子ではありません）。
「2-di-concrete の設計ではMockを差し込めない」ことを文章で示すためのサンプルです。

実際にコンパイルエラーになる本物のコードは trymock/try_mock.go にあります。
エディタで開くと赤線が出るので、そちらもあわせて見てください。

box_usecase.go で、BoxUseCase は以下のように定義されています。

    type BoxUseCase struct {
        repository *persistence.CachedBoxRepository
    }

    func NewBoxUseCase(repository *persistence.CachedBoxRepository) *BoxUseCase {
        ...
    }

NewBoxUseCase の引数は "*persistence.CachedBoxRepository" という
具体的な型で固定されています。interfaceではありません。

ここで、3-di-interface側と同じようにMockを自作してみます。

    type MockBoxRepository struct {
        Box *persistence.Box
        Err error
    }

    func (m *MockBoxRepository) Find(id int) (*persistence.Box, error) {
        if m.Err != nil {
            return nil, m.Err
        }
        return m.Box, nil
    }

このMockを使ってUseCaseのテストを書こうとすると、次のようになります。

    // このコードはコンパイルできない:
    //
    // useCase := NewBoxUseCase(
    //     &MockBoxRepository{
    //         Box: &persistence.Box{ID: 1, Number: 5},
    //     },
    // )
    //
    // コンパイルエラー:
    // cannot use mock (variable of type *MockBoxRepository)
    // as *persistence.CachedBoxRepository value in argument to
    // application.NewBoxUseCase
    //
    // なぜなら NewBoxUseCase は *persistence.CachedBoxRepository という
    // 「PostgreSQLの実装をキャッシュで包んだ構造体そのもの」を要求しており、
    // MockBoxRepository が同じメソッドセットを持っていても
    // 型としては全くの別物だからです。
    //
    // interfaceを挟んでいれば「Find(id int) (*Box, error) を満たすか」
    // だけが問われますが、ここでは「persistence.CachedBoxRepositoryという
    // 具体的な構造体そのものか」が問われてしまいます。

この結果、2-di-concrete 側でUseCaseをテストするには、実際にPostgreSQLへ接続する
box_usecase_test.go のような方法しか残されていません。
